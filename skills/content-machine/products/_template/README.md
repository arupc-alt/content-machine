# Reference file templates

These are the shapes setup sorts every company's files into, so the agents always find things in the same place. Companies never have to fill these in: they share whatever files they already have, in any format, and setup maps the content here. A company that wants a starting point can use them as a guide. Sections a company's files don't cover are listed as gaps, and filled only with the person's OK.

The areas setup looks for: product truth (`product-knowledge.md`), brand and voice (`brand-guide.md`), and writing rules and best practices (`style-guide.md`) are needed; the quality bar (`quality-checks.md`) is optional, since the built-in QA checks apply either way. Also optional: `links-and-ctas.md`, `competitors.md`, and `best-past-posts.md`.

How the company's files and the built-in rules work together:

- **The built-in guidelines are the defaults.** They're the best rules we have, and every product gets them.
- **The company's own guidelines win where the company chooses.** Where a file is looser than a built-in rule, or different from it (a higher reading level, em dashes, sentence-case headings), setup shows both with a short warning about the trade-off. A yes makes theirs the rule; a no keeps ours. A file rule that is only stricter (say, grade 4) is simply followed. Setup also sums up the files as a writing profile, each item marked as from their files or our default.
- **Some rules never change:** honesty and accuracy (no invented facts, statistics, quotes, reviews, people, or results, and real cited sources), claims that could create legal or compliance risk (no promised legal, tax, or compliance outcomes), privacy, and the pipeline's own safeguards, including how QA counts the score, decides a verdict, and limits rework.
- **Everything shared is stored in full.** Setup keeps the company's own words, never a summary. A long section is split into numbered parts, and every product gets an index, saved first, that lists every section, so a save that stops partway can pick up where it stopped and the agents can find what each piece needs.

Every file starts with the same short header, so anyone can see what it is and how fresh it is:

- **Product:** the product it covers (one set of files per product; positioning and claims don't transfer between products)
- **Used by:** which agents load it (Brief, Blog Writer, QA)
- **Source:** where the content came from (a questionnaire, an internal doc, the website)
- **Owner:** the person who approves changes and settles facts
- **Last updated:** the date

Text in [brackets] says what goes in each section. Replace it with the company's own words. Keep rules short and testable: "No em dashes" can be checked; "be engaging" can't.
